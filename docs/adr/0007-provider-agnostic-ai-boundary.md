# ADR-0007: AI 能力采用厂商无关的适配边界

## 状态
已采纳

## 背景

当前业务代码直接依赖智谱 SDK、智谱配置类和 `glm-4-flash` 模型名。AI 服务商、模型与参数散落在 Java、YAML 和前端代码中，导致更换服务商或模型时容易只改到一部分；AI 关闭时还会因缺少模型 Bean 而导致整个应用启动失败。

## 决策

在业务代码与 AI 服务商 SDK 之间增加轻量适配边界：

1. 业务层只使用厂商无关的 AI 配置、能力和 LangChain4j 通用模型接口。
2. 智谱 SDK、鉴权和模型构造集中在 `provider/zhipu` 适配实现中。
3. 通过 `AI_PROVIDER` 选择当前活动的服务商，首期只实现 `zhipu`。
4. AI 是可选的部署能力；关闭时核心业务仍可启动，AI 接口明确返回不可用。
5. 服务商、模型和可调参数统一由根目录 `.env` 注入，业务代码不硬编码模型名。

## 考虑过的方案

- 只重命名 `Zhipu` 类：改动小，但厂商 SDK 仍会泄漏到业务层。
- 立即实现完整多厂商框架：为尚不存在的需求引入过多抽象。
- 采用轻量适配边界：既解除厂商耦合，又保持当前单服务商场景简单。

## 后果

适配器内部仍会合理出现智谱专属类名；其他业务包不得直接引用智谱 SDK。新增服务商时只增加新的适配实现，不改智能体、控制器和前端接口。
