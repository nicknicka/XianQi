# ADR-0006: GitHub Actions CI 仅做构建验证

## 状态
已被 ADR-0009 取代

## 背景
CI/CD 流水线可以做很多事情：代码检查、单元测试、构建、镜像打包、部署等。需要确定第一阶段 CI 的范围。

## 决策
GitHub Actions CI 只做**构建验证**，确保代码可以正常编译打包。不做自动部署。

### CI Job 清单
1. **backend-build**：Maven 构建后端（JDK 17）
2. **admin-build**：npm ci + build 管理后台（Node 20）
3. **mobile-build**：npm ci + build:h5 H5 用户端（Node 20）

### 触发条件
- push 到 main 分支
- 所有 Pull Request

### 不包含的内容
- 单元测试（目前项目没有测试）
- ESLint/代码风格检查（可选但非必须）
- Docker 镜像构建推送（等有部署目标后再加）
- 自动部署（等有服务器后再加）

## 理由
1. **最小可用原则**：先保证最基本的——代码能构建
2. **无测试代码**：项目目前没有单元测试，加了也是空跑
3. **部署目标未确定**：还没有确定部署到哪里，CD 无从谈起
4. **快速反馈**：构建验证速度快，PR 能很快得到结果
5. **渐进式增强**：以后可以逐步加测试、lint、镜像构建、部署等

## 后果
### 正面
- 快速实现，不复杂
- 保证主干代码始终可构建
- PR 有基本的质量门禁
- 后续可以逐步扩展

### 负面
- 不做代码质量检查，坏代码也能过（只要能编译）
- 没有自动化部署，部署需要手动
