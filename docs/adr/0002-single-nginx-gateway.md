# ADR-0002: Docker Compose 单 Nginx 网关架构

## 状态
已采纳

## 背景
平台有三个对外入口：
1. 后端 API（Spring Boot，端口 8080）
2. 管理后台静态页面（Vue3 SPA）
3. H5 用户端静态页面（UniApp H5）

如果各自独立暴露端口，会导致：
- 前端跨域问题
- 需要分别配置 SSL
- 端口管理混乱
- 不便于统一入口

## 决策
使用单个 Nginx 容器作为统一网关，通过路径路由到不同服务：

| 路径 | 目标 |
|------|------|
| `/` | 301 重定向到 `/h5/` |
| `/admin/` | 管理后台静态文件 |
| `/h5/` | H5 用户端静态文件 |
| `/api/` | 后端 Spring Boot |
| `/api/ws` | 后端 WebSocket（特殊代理配置） |
| `/api/uploads/` | 上传文件（Nginx 直接 serve） |

Nginx 同时负责：
- 静态资源缓存
- Gzip 压缩
- 安全响应头
- 访问日志

## 理由
1. **单入口点**：用户只需要记住一个域名/IP
2. **同域避免跨域**：前端和 API 在同一个域名下，无需配置 CORS
3. **配置集中**：SSL、限流、缓存等配置统一管理
4. **性能更好**：静态资源由 Nginx 直接提供，不占用后端资源
5. **扩展灵活**：未来加新服务只需增加 location 配置

## 后果
### 正面
- 部署简单，一个 compose up 就全部启动
- 前端不需要配置跨域
- 静态资源访问性能好
- 生产环境加 SSL 很方便

### 负面
- Nginx 是单点故障（但单机部署本来就是单点）
- 前端路由需要配置 try_files 支持 SPA history 模式
- 子路径部署需要前端构建时配置 base
